# Superintelligence SG 维护协作规则

适用：Mac ChatGPT App（「SI SG Website 3」及其绑定的周一 22:00 / 周四 10:00 定时维护任务）与 SI 新加坡助手。
最后更新：2026-11-14，由劲涛确认后生效。

## 1. 分工

| 角色 | 负责 |
|---|---|
| Mac ChatGPT App | 调研来源；更新 .ai 与 .si 内容；开 PR；.si 的 Sites 发布（经劲涛确认） |
| SI 新加坡助手 | 读取每次维护报告；核对来源；审 PR；把需要的内容同步到 .com / .org；向劲涛汇报 |
| 劲涛 | 确认 .si 发布；最终拍板 |

## 2. 改代码必须走 PR，不直接推 main

1. 每次维护新建分支：`maint/YYYY-MM-DD`。
2. 改完开 PR，标题：`SI 维护 YYYY-MM-DD（周一|周四）`，加标签 `si-maintenance`。
3. PR 描述必须写第 3 节的维护报告。
4. 不要自己合并。SI 新加坡助手核对来源并审查后合并；有问题会在 PR 里留言。
5. 根目录与 `dist/`（如有）必须同步并逐字节一致。
6. 不改：域名、DNS、.org 的 Worker / D1、动效文件（`motion-*.css/js`、`si-ripple.*`）、页面 head 结构，除非劲涛明确要求。

## 3. 维护报告（每次都要交，没有变化也要交）

没有代码改动时，不开 PR，改为在本仓库开一个 issue（同样的标题和标签）。

报告内容：
1. 检查的时间范围与来源列表。
2. 新增 / 更新条目：名称、变化内容、原始来源链接、来源发布日期。
3. 本次改动：文件 / 页面、版本号变化（如 Field Note v1.2 → v1.3）。
4. 同步建议：逐条标出是否要同步到 .com / .org / .si / .ai。
5. 未核实或存疑的内容单独列出，标「未核实」。
6. 没有变化时写「本次无变化」。

## 4. 内容规则

- 只写有真实来源的事实，每条附原始链接；优先政府、机构、论文、官方新闻稿。
- 不编造人名、引文、数字；引文必须能在原文找到。
- 涉及具体人物时，写来源里给出的身份，不做推测。

## 5. 发布顺序

1. ChatGPT App 开 PR → 2. SI 新加坡助手核对、审查、合并 → 3. .ai 由 GitHub Pages 自动部署；.si 由劲涛在 Mac ChatGPT App 发布 Sites → 4. SI 新加坡助手线上验收并同步 .com / .org → 5. 向劲涛汇报。
